# Faculty Citation Review — מערכת בדיקת ציטוטים לתיקי קידום

מערכת מקומית לספריית הפקולטה לארכיטקטורה ובינוי ערים בטכניון. המערכת מפיקה דוח ציטוטים לחוקר/ת לפי הנוהל "בדיקת ציטוטים להערכות חוקרים" (טיוטה 1.0, שלבים א–ו).

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy (SQLite כברירת מחדל, אפשר לעבור ל-PostgreSQL), PyMuPDF, python-docx, openpyxl, httpx.
- **Frontend:** React + TypeScript (Vite), עברית מלאה ו-RTL. השרת מגיש את הממשק בכתובת אחת.
- **בדיקות:** pytest — 44 בדיקות יחידה ואינטגרציה.

## התקנה והפעלה (מחשב של עובד/ת ספרייה)

דרישות: Python 3.11 ומעלה, Node.js 18 ומעלה (נדרש רק לבניית הממשק).

**Windows:** הפעילו פעם אחת את `scripts\install.bat`. לאחר מכן, בכל הפעלה: `scripts\run.bat`.

**Linux / macOS:**
```bash
scripts/install.sh
```
```bash
scripts/run.sh
```

פתחו את הכתובת http://127.0.0.1:8000. בהפעלה הראשונה יוצרים משתמש מנהל. השרת מאזין רק למחשב המקומי. להפעלה ברשת הפקולטה יש להחליף את `--host` ולהציב את השרת מאחורי HTTPS.

**הרצת הבדיקות:**
```bash
cd backend && ../.venv/bin/python -m pytest
```

**פיתוח הממשק:** מריצים את `scripts/run.sh` ובמקביל `cd frontend && npm run dev`. הממשק יעלה בכתובת http://localhost:5173.

## הרשאות ומפתחות API — יש לבדוק לפני חיבור למאגרים

המפתחות נשמרים רק במשתני סביבה, בקובץ `.env` שבתיקיית המערכת (העתק של `.env.example`). הם לא נשמרים בקוד, בבסיס הנתונים, ביומן השינויים או בדוחות. המערכת עובדת גם ללא מפתחות: אפשר להזין נתונים ידנית ולייבא קובצי ייצוא מהמאגרים.

| מאגר | משתנה | מה נדרש | מה מאפשר |
|---|---|---|---|
| Scopus | `SCOPUS_API_KEY` | מפתח מ-Elsevier Developer Portal המשויך למנוי הטכניון | איתור לפי DOI או כותרת+מחבר+שנה, Cited by, EID |
| Scopus | `SCOPUS_INST_TOKEN` | אופציונלי, טוקן מוסדי מ-Elsevier | שימוש מחוץ לרשת הטכניון |
| Scopus | הרשאת `view=COMPLETE` | זכאות מוסדית | כל מחברי המאמרים המצטטים ומזהי Author ID. בלעדיה זמין רק המחבר הראשון, והרשומות מסומנות כ"רשימת מחברים חלקית" |
| Web of Science | `WOS_STARTER_API_KEY` | Web of Science Starter API (Clarivate Developer Portal) | איתור ו-Times Cited, WoS UID |
| Web of Science | `WOS_EXPANDED_API_KEY` | Web of Science API Expanded (מנוי נפרד) | רשימת המצטטים (`/citing`). בלעדיו מייבאים קובץ ייצוא מ-WoS |
| Google Scholar | — | אין API ציבורי | הזנה ידנית בתהליך מונחה וקישור ישיר לרשומה. **אין scraping ואין עקיפת CAPTCHA, robots.txt או חסימות** |

> הקוד שמתחבר ל-Scopus ול-WoS נבדק מול תשובות מדומות בפורמט של הספקים (`tests/test_adapters.py`), אבל עדיין לא מול השירותים האמיתיים. כשיתקבלו מפתחות, יש להריץ בדיקה על כמה פרסומים מוכרים ולהשוות לתוצאות שמופיעות באתרי המאגרים.

## תהליך העבודה (7 מסכים)

1. **פתיחת תיק:** שם באנגלית, וריאנטים של השם, ORCID, Scopus Author ID ו-ResearcherID. העלאת קורות חיים (PDF/DOCX). הקובץ נשמר עם חתימת SHA-256.
2. **בדיקת רשימת הפרסומים:** המערכת מזהה את הפרק PUBLICATIONS ואת תתי-הפרקים. הטקסט המקורי נשמר כפי שהוא. השדות המובנים ניתנים לתיקון. רשומות לא מאוחדות אוטומטית, ואפשר להוסיף פרסום שלא חולץ.
3. **מדיניות** (רק מנהל רשאי לשנות): שפות, סטטוסים (Published / Online first / Accepted / Submitted / Unpublished), סוגי פרסום, הגדרת ציטוט עצמי A או B, ומדיניות לעמודות H–I. פרסום מוחרג נשאר ברשימה עם סיבת ההחרגה.
4. **טבלת פרסומים ומאגרים:** חיפוש ב-API, או הזנה ידנית של רשומה מאומתת, או סימון "לא מאונדקס" / "דורש אימות". רשומה נבחרת אוטומטית רק כשההתאמה חד-משמעית: DOI זהה, או כותרת+שנה+מחבר בלי רשומה מתחרה קרובה.
5. **פרסומים מצטטים:** משיכה מה-API, ייבוא קובץ או הזנה ידנית. לכל רשומה מוצג סיווג לפי הגדרה A ולפי הגדרה B עם הסבר. אפשר לשנות סיווג ידנית (חובה לנמק) ולאשר אותו.
6. **בקרת איכות:** התראות על חסרים, כפילויות, כותרות דומות, תוצאות חלקיות ופערים בין סך הציטוטים למספר הרשומות. "התיק הוכן" מסמן העובד/ת המכין/ה, ואת האישור נותן/ת **עובד/ת אחר/ת** בתפקיד בודק/ת.
7. **יצירת Excel:** הדוח נוצר לפי תבנית הפקולטה (או תבנית ברירת המחדל), עם גיליון `Audit Trail` מלא. דוח שלא אושר בבקרה מסומן כ-`draft`.

## כללי חישוב

- **0** = הפרסום אותר ונבדק ולא נמצאו ציטוטים. **"לא מאונדקס"** = הפרסום לא נמצא במאגר. **"לא נבדק"** = הבדיקה לא הושלמה. **"דורש אימות"** = לא ניתן לקבוע בוודאות. ערך חסר לעולם לא מוחלף ב-0.
- לא עצמיים = סך הציטוטים − עצמיים, ומחושב **רק** כשכל רשומות המצטטים סווגו. אחרת התוצאה מוצגת כ-`≥N (זמני; X לא מסווגים)`.
- כל מאגר מוצג בנפרד. כל פרסום מצטט נספר פעם אחת בתוך אותו מאגר.
- שתי ההגדרות (A ו-B) מחושבות תמיד. בדוח מופיעה ההגדרה שנבחרה במדיניות.
- **זיהוי מחברים:** קודם לפי מזהים (ORCID, Scopus Author ID, ResearcherID). מזהה שונה פירושו אדם אחר. התאמה לפי ראשי תיבות או לפי שם משפחה בלבד עוברת לאימות ידני. שם מלא זהה בלי מזהה נחשב התאמה (ניתן לשנות במדיניות). מצטט בלי פרטי מחברים, או עם רשימת מחברים חלקית, לא יסווג כ"לא עצמי".
- **H–I:** אפשר לבחור "סכום המאגרים" (מצוין במפורש שאינו ייחודי), "ציטוטים ייחודיים", "המאגר עם הערך הגבוה" או "ריק". ציטוטים ייחודיים מחושבים רק כשכל הרשימות מלאות ומסווגות: כפילויות מוסרות לפי DOI או לפי כותרת+שנה זהות, ומצטט שסווג אחרת במאגרים שונים מסומן לאימות.

## תבנית Excel

- A = הפרסום · B/C = WoS לא עצמיים/עצמיים · D/E = Scopus · F/G = Google Scholar · H/I = סיכום.
- שורת הכותרת מזוהה אוטומטית (שורה שבה מופיעות המילים "עצמי" / "self").
- **תבנית שכבר מכילה את רשימת הפרסומים:** כל שורה מותאמת לפרסום לפי דמיון טקסט (≥85%) ומתמלאת במקומה. הסדר והקטגוריות נשמרים. שורות שלא הותאמו מדווחות, ופרסומים שחסרים בתבנית נוספים בסוף עם כותרת.
- **תבנית ריקה:** השורות נבנות לפי סדר קורות החיים והקטגוריות שלהם.
- בתחתית הגיליון נכתבים תאריכי איסוף הנתונים, הגדרת הציטוט העצמי ומקרא הסימונים.

## ייבוא רשימות מצטטים

הפורמטים מזוהים אוטומטית לפי שמות העמודות:
- **ייצוא CSV מ-Scopus** (Cited by → Export): `Author full names` כולל Author ID, `Title`, `Year`, `DOI`, `EID`.
- **ייצוא מ-Web of Science** (Tab-delimited): `AF`, `TI`, `PY`, `DI`, `UT`, `OI`, `RI`.
- **תבנית המערכת:** `sample_data/citing_import_template.csv`. בעמודת `publication` נכתב מספר פנימי (#) או `cv:<מספר בקו"ח>` לייבוא מרוכז (`POST /api/cases/{id}/citing/{provider}/import`).
- **Google Scholar:** ייבוא רק של קובץ שהושג בדרך מותרת ובהתאם לרישיון.

## אבטחת מידע

- כל הנתונים נשמרים מקומית בתיקייה `data/` (בסיס נתונים, קבצים שהועלו ודוחות). קורות החיים **לא** נשלחים לשום שירות חיצוני, כולל שירותי AI.
- משתמשים ותפקידים: מנהל (מדיניות, משתמשים, גיבוי), עובד/ת ספרייה (הכנת תיקים), בודק/ת (אישור שני ושינוי סיווג). הסיסמאות שמורות כ-hash מסוג PBKDF2. תוקף טוקן התחברות הוא 12 שעות.
- יומן שינויים (append-only) מתעד כל פעולה: מי, מתי, מה היה ומה השתנה. היומן מופיע גם במסך הניהול וגם בגיליון Audit Trail.
- **גיבוי:** כפתור במסך הניהול, או הרצת `scripts/backup.sh` (מתאים להפעלה מתוזמנת יומית). הגיבוי הוא קובץ ZIP עם עותק עקבי של בסיס הנתונים ושל הקבצים. נשמרים 30 הגיבויים האחרונים.
- **מעבר ל-PostgreSQL:** מגדירים `FCR_DATABASE_URL` ומתקינים driver (למשל `psycopg`). במקרה כזה הגיבוי נעשה באמצעות `pg_dump`.

## נתוני דוגמה

`sample_data/generate_samples.py` יוצר קורות חיים לדוגמה (PDF ו-DOCX), ייצוא Scopus לדוגמה ותבנית דוח. **כל הפרטים בקבצים אלה בדויים:** החוקרת "Dana Example", כתבי העת, מזהי DOI עם הקידומת `10.99999` (שאינה קיימת) ומזהי Author ID. הקבצים מיועדים לבדיקות ולהדגמה בלבד, ואין להציגם כתוצאות אמיתיות.
